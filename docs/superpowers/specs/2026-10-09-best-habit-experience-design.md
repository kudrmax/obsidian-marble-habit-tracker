# Tiny Habits — дизайн MVP

Дата: 2026-10-09
Статус: на ревью у автора

## 1. Цель

Плагин Obsidian для отслеживания привычек по методологии «Нанопривычек» Би Джей Фогга.
Пользователь каждый день в 1–2 тапа отмечает привычки прямо в Obsidian, видит цепочки и статистику,
а данные лежат в Markdown-заметках и синкаются между ноутбуками через obsidian-git без конфликтов.

Ориентиры:
- **хранение** — как у Habit Tracker 21: одна привычка = одна заметка, всё во frontmatter;
- **функции** — простота Loop Habit Tracker: сетка дней, экран привычки со статистикой;
- **UI** — минималистичный, в стиле Obsidian и Quick Capture, не как у Loop;
- **UX сетки** — как в Singularity: отмеченные дни сливаются в цепочки.

## 2. Продуктовые принципы

1. **Рецепт Фогга.** Привычка — это набор независимых компонентов: якорь, нанодействие, полное действие, празднование.
2. **Нано — полный успех.** Полное действие — бонус, к которому растёшь. Это не планка успеха.
3. **Празднование встроено в отметку.** Сразу после отметки на экране появляется фраза-празднование из рецепта и конфетти.
4. **Без давления.** Никаких красных крестов. Пустой день — просто пустой: плагин его не трактует, ни о чём не спрашивает и не напоминает.
5. **Без магии.** Плагин не додумывает, не группирует и не делает выводов за пользователя. Любое правило формулируется одной фразой и видно в UI.
6. **Причина пропуска обязательна.** Явная отметка «не получилось» без причины невозможна. Причины — материал для переделки рецепта.

## 3. Объём MVP

Входит:
- вкладка «Привычки» с сеткой дней;
- отметки «нано», «полное», «не получилось (причина)»;
- празднование с конфетти;
- экран привычки: рецепт, подсказка о переделке, статистика за 30 дней, календарь, серии, список пропусков, история рецепта;
- создание привычки, изменение компонентов с историей, архивирование;
- расписание «каждый день» или «по дням недели»;
- настройки.

Не входит и **не закладывается**:
- напоминания и уведомления — не нужны вообще.

Не входит в MVP, но архитектура позволяет добавить:
- числовые привычки (значение, единица, пороги);
- частоты вида «N раз в неделю»;
- code block для встраивания сетки в заметки;
- статистика по версиям рецепта.

Отклонено:
- группировка по якорям и цепочки привычек;
- рой поведений и карта фокуса;
- разбор неразмеченных дней;
- сводки причин;
- автоматическое отслеживание ручных правок истории;
- поле «время якоря».

## 4. Модель предметной области

### 4.1 Привычка

| Поле | Смысл |
|---|---|
| имя | имя файла заметки |
| `schedule` | компонент: дни недели, когда привычка запланирована |
| `anchor` | компонент: якорь, текст («После того как я…») |
| `tiny` | компонент: нанодействие, текст |
| `full` | компонент: полное действие, текст, необязателен |
| `celebration` | компонент: празднование, текст, необязателен |
| отметки | не больше одной отметки на дату |
| `order` | число для ручной сортировки, необязательно |
| `archived` | скрыть из сетки, данные сохраняются |

### 4.2 Компонент с историей

Компонент — это упорядоченный список версий, **первая версия — актуальная**.
У версии есть поля: `value`, `since` (дата, с которой действует) и необязательное `replaced_because`.
Поле `replaced_because` пишется **в старую версию** и отвечает на вопрос «почему эта версия перестала подходить».

Операции:
- **заменить** — новая версия встаёт первой с `since` = сегодня, а причина (по желанию) записывается в бывшую актуальную;
- **исправить** — меняет `value` актуальной версии без новой строки в истории. Нужно для опечаток. В UI это явный отдельный пункт.
- `at(date)` — версия, действовавшая в эту дату. Нужна для расписания в прошлом.

Если версия заменяется в тот же день, когда создана, она перезаписывается и новая строка не появляется.

### 4.3 Расписание

Значение — подмножество дней недели `[mon … sun]`, в котором минимум один день. «Каждый день» означает все семь.
День считается запланированным, если его день недели входит в версию расписания, действовавшую в эту дату.
До первой версии (раньше создания привычки) дни не запланированы.

### 4.4 Отметка дня

`tiny` | `full` | `missed(reason)`, где `reason` — непустая строка после trim.
Отметить можно **любой** прошедший день или сегодняшний, даже если он не по расписанию. Будущие дни отметить нельзя.

### 4.5 Статистика (окно — последние 30 дней, включая сегодня)

- **Процент** = выполненные запланированные дни / запланированные дни × 100. Выполненный день — с отметкой `tiny` или `full`.
  Сегодняшний день входит в знаменатель, только если у него уже есть отметка: день ещё не закончился.
  Подпись: «22 из 30 запланированных дней».
- **Разбивка по запланированным дням окна:** нано, полное, не получилось, пусто.
- **Серия** — подряд идущие запланированные дни с выполнением. Дни вне расписания серию не прерывают и не продлевают.
  Запланированный день без выполнения (пустой или `missed`) серию прерывает.
  Сегодняшний пустой день текущую серию не прерывает.
- **Текущая серия, лучшая серия, список серий.** Для каждой серии хранятся длина, дата начала и конца. Показываются 5 самых длинных плюс текущая.
- **Всего выполнений** — все отметки `tiny` и `full` за всё время, включая дни вне расписания.

### 4.6 Правило подсказки «переделай рецепт»

Если после последней отметки `tiny` или `full` (или с начала истории, если выполнений нет) стоит **≥ N** отметок `missed`,
показывается подсказка. Пустые дни игнорируются. N задаётся в настройках, по умолчанию 3.
Текст подсказки: «N "не получилось" подряд после последнего выполнения. Может, переделать рецепт?»

## 5. Формат хранения

Папка привычек задаётся в настройках, по умолчанию `Habits`. Привычками считаются только `.md`-файлы прямо в этой папке, подпапки игнорируются.
Тело заметки плагин не трогает.

```yaml
---
order: 1
schedule:
  - value: [mon, tue, wed, thu, fri, sat, sun]
    since: 2026-09-01
anchor:
  - value: Поставлю кружку в раковину
    since: 2026-09-20
  - value: Выпью кофе
    since: 2026-09-01
    replaced_because: С кофе забывал — якорь размытый
tiny:
  - value: 2 приседания
    since: 2026-09-05
  - value: 1 приседание
    since: 2026-09-01
full:
  - value: 15 минут зарядки
    since: 2026-09-01
celebration:
  - value: «Есть!» + кулак
    since: 2026-09-01
done_tiny:
  - 2026-10-08
  - 2026-10-06
done_full:
  - 2026-10-09
missed:
  - date: 2026-10-07
    reason: Пил кофе не дома
archived: false
---
```

Правила:
- все ключи на английском, даты в формате `YYYY-MM-DD`, в локальном часовом поясе;
- списки отметок отсортированы по убыванию даты, новые сверху; список версий тоже идёт сверху вниз от новой к старой;
- дата встречается не больше чем в одном из списков `done_tiny`, `done_full`, `missed`. При смене отметки дата переносится из списка в список;
- пустые списки, а также `full` и `celebration` без версий во frontmatter не пишутся; `archived` пишется только со значением `true`;
- неизвестные ключи frontmatter сохраняются как есть.

**Чтение невалидных данных.** Если в заметке нет `anchor`, `tiny` или `schedule`, лежит кривая дата или одна дата стоит в двух списках, заметка помечается как битая.
В сетке она показывается приглушённой строкой с текстом «Не удалось прочитать: <причина>» и открывается по тапу.
Плагин не исправляет её автоматически и не пишет в неё.

## 6. UI

### 6.1 Вкладка «Привычки»

Открывается иконкой на ленте и командой «Open habits». Это обычная вкладка, на телефоне — полноэкранный вид.

- Строки — неархивные привычки, отсортированные по `order` по возрастанию. Привычки без `order` идут в конце, по имени.
- В строке название, а под ним мелким текстом «нано: … · полное: …».
- Столбцы — дни, сегодня справа. Видно столько дней, сколько помещается по ширине вкладки (на десктопе обычно 14–21, на телефоне меньше).
  История листается **горизонтальным скроллом** (свайп, трекпад, колесо с Shift) без ограничения в прошлое, а также стрелками ‹ › на ширину экрана. Дальше сегодняшнего дня пролистать нельзя.
  Шапка с датами и колонка с названиями привычек при скролле остаются на месте.
- Вид клетки:

| Отметка | Вид |
|---|---|
| нано | светлый круг акцентного цвета |
| полное | насыщенный круг |
| не получилось | серый перечёркнутый круг |
| пусто | контур |

  Пустой день вне расписания показан пунктирным контуром. Соседние выполненные дни соединяются перемычкой, получается цепочка.
- Если для привычки сработало правило подсказки (4.6), у её названия стоит маленький значок ↻.
- Пустое состояние — «Привычек пока нет» и кнопка «Новая привычка». Кнопка «+» есть всегда.

**Взаимодействие с клеткой:**
- **тап** (клик) по клетке с нано, полным или пустой: пусто → нано → полное → пусто. После отметки нано или полного показывается празднование;
- **тап** по клетке «не получилось» открывает окно причины с текущим текстом и кнопкой «Очистить»;
- **долгое нажатие** (ПКМ на десктопе) по любой клетке открывает окно «Почему не получилось?»;
- тап по названию открывает экран привычки.

### 6.2 Празднование

Полупрозрачный оверлей поверх вида примерно на 1,5 секунды. Закрывается сам или по тапу.
Содержимое:
- крупно — актуальное празднование, а если его нет, название привычки;
- ниже — «<привычка> · нано/полное» (если крупно уже название, здесь только уровень);
- ещё ниже — «серия N».

Конфетти включается и выключается в настройках, по умолчанию включено.
Если отметка ставится на прошлый день, празднование тоже показывается.

### 6.3 Окно «Почему не получилось?»

Заголовок, «<привычка> · <день недели>, <дата>», актуальный на эту дату якорь и поле причины.
Кнопка «Сохранить» неактивна, пока поле пустое. Enter сохраняет. Есть кнопка «Отмена».
Если у дня уже стоит «не получилось» (например, отметил по ошибке), внизу есть ряд явных действий:
**«Сделал нано»**, **«Сделал полное»**, **«Очистить»**. Первые два заменяют отметку и причину на выполнение и показывают празднование. «Очистить» делает день пустым.

### 6.4 Экран привычки

Отдельная вкладка, одна колонка с прокруткой:
1. Название и расписание («каждый день» или «пн, ср, пт»).
2. Рецепт: якорь, нано, полное, празднование, расписание. Тап по значению открывает окно компонента (6.5).
3. Подсказка (4.6), если сработала, с кнопкой «Переделать». Кнопка открывает выбор компонента для изменения.
4. Последние 30 дней: процент, подпись, текущая и лучшая серия, всего выполнений, полоса разбивки с легендой.
5. Календарь — тепловая карта, по умолчанию последние 12 месяцев, горизонтальным скроллом листается назад на всю историю привычки. Дни, в которые начинала действовать новая версия любого компонента, обведены рамкой. Тап по такой клетке показывает, что изменилось.
6. Серии.
7. «Не получилось» — список «дата — причина», от новых к старым.
8. История рецепта — список «дата · компонент · было → стало», под ним `replaced_because`, если причина есть. Последняя строка — «создана».
9. Меню: «Архивировать», «Открыть заметку». Вернуть из архива — убрать `archived` в Properties заметки.

### 6.5 Окно компонента

Показывает текущее значение и две явные кнопки:
- **«Заменить»** — новое значение и поле «Почему старое не подошло? (можно пропустить)»;
- **«Исправить»** — правка текста без истории.

Для расписания вместо текста — выбор дней недели.

### 6.6 Новая привычка

Форма читается как рецепт:
- «После того как я…» — якорь;
- «я сделаю (нано)»;
- «а стремлюсь к (полное)» — необязательно;
- «и отпраздную»;
- дни недели — по умолчанию все;
- название.

Обязательны: название, якорь, нано. Полное и празднование — по желанию. Если заметка с таким названием уже есть, форма показывает ошибку.
У всех компонентов `since` = сегодня. Заметка создаётся в папке привычек; если папки нет, она создаётся.

### 6.7 Настройки

| Настройка | По умолчанию |
|---|---|
| Папка привычек | `Habits` |
| N для подсказки | 3 |
| Конфетти | вкл |

## 7. Архитектура

TypeScript без UI-фреймворков, слои как в Quick Capture.

```
src/
  domain/          чистая логика, без Obsidian
    LocalDate.ts     дата без времени: parse/format, сравнение, сдвиг, день недели
    Component.ts     Component<T>: current, at(date), replace, correct
    Schedule.ts      Weekday, isScheduled(date)
    DayMark.ts       tiny | full | missed(reason), cycle()
    Habit.ts         агрегат: компоненты, отметки, инварианты
    Stats.ts         окно 30 дней, разбивка, серии, итог
    RedesignRule.ts  правило 4.6
    Clock.ts         источник «сегодня»
  application/
    ports.ts         HabitRepository, HabitEntry (Habit | Broken)
    HabitService.ts  cycle, setMissed, clear, replaceComponent, correctComponent, create, archive
  infrastructure/
    HabitCodec.ts                 frontmatter ↔ Habit, чистая функция
    FrontmatterHabitRepository.ts metadataCache + processFrontMatter + vault
  ui/
    HabitsView.ts, HabitScreenView.ts, CelebrationOverlay.ts,
    MissReasonModal.ts, ComponentModal.ts, HabitFormModal.ts, SettingsTab.ts
  settings.ts
  main.ts          сборка зависимостей, регистрация видов и команд
```

Решения:
- **Домен не знает про Obsidian и YAML.** Формат живёт только в `HabitCodec`. Новый тип привычки или частота меняют домен и кодек, а не UI и сервис.
- **Запись** — только `fileManager.processFrontMatter`. Кодек переписывает свои ключи и не трогает чужие.
- **Чтение** — `metadataCache.getFileCache(file).frontmatter`.
- **Внешние изменения** (obsidian-git, ручная правка) приходят через `metadataCache.on("changed")`, `vault.on("delete" | "rename" | "create")` по папке привычек. Открытые виды перечитывают данные и перерисовываются, больше ничего не происходит.
- Сервис возвращает ошибки домена (пустая причина, будущая дата, дубликат имени), а UI показывает их через `Notice`.

## 8. Тестирование

- vitest, заглушка `obsidian` в `tests/stubs`, как в Quick Capture.
- Юнит-тесты домена: `LocalDate`, `Component` (replace, correct, at, перезапись в тот же день), `Schedule` (смена расписания в прошлом), `DayMark.cycle`, `Stats` (процент, сегодняшний день, серии через дни вне расписания, всего), `RedesignRule` (пустые дни игнорируются, сброс после выполнения).
- `HabitCodec`: прямое и обратное преобразование на примере из раздела 5, сохранение неизвестных ключей, все виды битых данных.
- `HabitService` с in-memory репозиторием.
- UI и инфраструктура проверяются вручную в Obsidian: сборка и `deploy.mjs` в `~/Obsidian/.obsidian/plugins/tiny-habits`.
